# Local word/phrase teacher pilot

Started 2026-11-04 (America/Los_Angeles), continuing after midnight on Nov 5. This is the local testing stage before a separately authorized MI300 production deployment. No cloud instance or paid API is used.

## Scope and reproducibility

Model identity and parameter scopes are recorded in `parameter-summary.json`, with official pinned configs and GGUF tensor directories in `model-evidence/`:

- **Qwen3.6-35B-A3B**: official language model claim **35B total / about 3B activated per token**. Forty main layers combine Gated DeltaNet and gated full attention with MoE FFNs: 256 routed experts, top-8 plus one shared. HF class is `Qwen3_5MoeForConditionalGeneration`; local GGUF architecture is `qwen35moe`. The tested GGUF contains **34,660,610,688 stored tensor elements**, without an extra MTP block. [Official card](https://huggingface.co/Qwen/Qwen3.6-35B-A3B/blob/995ad96eacd98c81ed38be0c5b274b04031597b0/README.md), [config](https://huggingface.co/Qwen/Qwen3.6-35B-A3B/blob/995ad96eacd98c81ed38be0c5b274b04031597b0/config.json).
- **Qwen3.8-27B**: official language model claim **27B dense**, 64 main layers with hybrid Gated DeltaNet / gated attention and dense FFNs. It has no sparse-MoE active-parameter statistic: the dense backbone participates at every token; this is not an exact count of physically touched embedding entries. HF class is `Qwen3_5ForConditionalGeneration`; GGUF architecture is `qwen35`. The GGUF stores **27,320,697,856 tensor elements**, including **424,699,392** in its optional extra MTP block; excluding that block gives **26,895,998,464**. Effective `/props` reports `speculative.types=none`, so MTP drafting was not used. [Official card](https://huggingface.co/Qwen/Qwen3.8-27B/blob/1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0/README.md), [config](https://huggingface.co/Qwen/Qwen3.8-27B/blob/1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0/config.json).
- **GLM-4.7-Flash**: official rounded claim **30B total / about 3B activated per token (30B-A3B)**. Config is `Glm4MoeLiteForCausalLM`: 47 main layers, first layer dense, 64 routed experts with top-4 plus one shared in MoE layers. GGUF uses the `deepseek2` serialization architecture; that identifier does not rename the model to DeepSeek. The tested GGUF stores **29,943,393,920 tensor elements**, with no optional MTP block in its directory. [Official card](https://huggingface.co/zai-org/GLM-4.7-Flash/blob/7dd20894a642a0aa287e9827cb1a1f7f91386b67/README.md), [config](https://huggingface.co/zai-org/GLM-4.7-Flash/blob/7dd20894a642a0aa287e9827cb1a1f7f91386b67/config.json).

Official HF safetensors metadata for the **full published bundles** reports 35,951,822,704 / 27,781,427,952 / 31,221,488,576 elements respectively. Those scopes include published components beyond the tested text core (the Qwen configs include vision and MTP; GLM config includes a next-token prediction layer). The parameter evidence does not attest the converter's exact upstream commit merely because a current official config was retrieved. Local dimensions/architectures are independently captured from already SHA-verified files. All exact local counts are sums of tensor-dimension products, **not Q8 byte-size estimates**, and may include auxiliary/buffer tensors; they are not claims that every stored element is independently trainable or used at every step. The model-card MoE activation figures are rounded official claims, not recomputed from file size.

The three Q8_0 candidates are existing Qwen3.6-35B-A3B, Qwen3.8-27B and GLM-4.7-Flash. `assets.lock.json` pins the original and conversion repositories, exact revisions, sizes and full SHA-256. The two new models were downloaded; the existing model was rehashed and reused. All weights are public and ungated. Large weights and backend binaries are stored in ignored `models/` directories.

The backend is llama.cpp b12125 (`7d516e25ead4653169236b3f90d13f7bd8629724`), official Windows Vulkan x64 release. All models run sequentially on the Radeon 8060S. The fixed protocol uses one slot, context 8192, full requested GPU offload, 8 CPU threads, batch/ubatch 512, automatic Flash Attention, temperature 0, seed 7391, max output 2048, reasoning disabled and the same JSON schema. See `protocol.json` for the exact settings. Detailed logs from the second server launch onward use verbosity 4 to expose GPU allocations; the first Qwen3.6 launch used the default verbosity 3. This diagnostic difference does not change inference settings.

The uniform greedy profile is an experimental control, not a per-vendor optimal sampling recipe or a test of each model's capability ceiling. No prompt, sampling setting or completed sample is changed in response to intermediate results or the later request for more parameter evidence.

`results/<model>/server-*.json` records each owned process, command, load/stop times, backend executable hash and effective `/props` including chat template. `.log` files preserve model loading and server diagnostics. Only the process created by the runner is stopped. Each `attempts/*.json` saves the full request, unmodified response, usage, wall time, timestamps and validation outcome. Document records link attempts and the selected result. A hard-invalid or output-truncated result gets at most one uniform repair request. The first hard-valid result is selected; no semantic best-of-N or post-hoc correction is applied.

All six owned server sessions are closed after completing their assigned records. Their Windows `Popen.terminate()` shutdown produces exit code 1; this is the recorded runner-initiated shutdown, not an observed inference crash. A final host process/port check is saved separately.

`cache_prompt=false` is requested, but llama.cpp logs can still show its internal prefix/checkpoint reuse. The preserved `timings.cache_n`, prompt/decode timings and command are the evidence for effective behavior. Do not interpret these measurements as an isolated uncached kernel benchmark or predict MI300 tokens/s from them. Q8_0 does not remove architectural/backend differences between candidates, and these third-party conversions do not establish BF16 or FP8 parity.

## Inputs and review policy

`inputs/pilot28.jsonl` contains 24 project-authored diagnostic cases plus the four unchanged independent MDN review candidates from v0.2. It covers lexical ambiguity, entity roles, negation, conditions/time, quantities, English morphology, whitespace, combining characters, emoji/non-BMP characters, code and quoted instructions. The two required phrases, 研究生命起源 and 研究生命科学, are both present. The old FMM 研究生｜命 error is kept distinct from offline jieba's 研究｜生命｜起源.

`inputs/all100.jsonl` adds 72 deterministic variations from eight templates. Inputs, prompt, schema, budgets, retry policy and the 12-case primary review selection were fixed before inference. The 72 are a repeatability/stress cohort, not 72 independent natural examples; report their results separately. Parallel MDN topics and template variations retain family IDs. No training split is assigned.

Every primary review case is inspected for every model, including failures. `codex-review.json` holds actual Codex observations of raw outputs: plausible words, phrase coherence, attachment/negation/quantity risks and acceptable ambiguities. This is an **unblinded assessment by the same Codex agent**, not independent human gold, and no semantic accuracy percentage is claimed. The saved selection file includes a seed available for ordering; this run does not claim a blind study. Supplementary inspection of hard failures is diagnostic and is not added to the primary denominator. The four MDN cases are now consumed in this exploratory teacher selection; any next protocol confirmation requires fresh held-out natural texts.

## What the checker establishes

`validate.py` checks JSON shape, original-text reconstruction, word/phrase budgets, sequential coverage and code-point/UTF-8 spans, explicit protected-string boundaries, separated whitespace and detached combining marks/joiners. It constructs ordered word children and a two-scale phrase forest for hard-valid candidates, including one-child passthrough flags. A hard pass is **not** a lexical correctness test: a multiword Chinese child with no spaces, punctuation glued to a word, or an entire clause called a phrase may still need rejection in qualitative review. The tests deliberately demonstrate this distinction.

`quality-standards.json` spells out the label rule, implemented hard checks, qualitative criteria and an overlapping six-category error taxonomy: source rewriting/omission, whitespace/punctuation, Unicode integrity, lexical boundaries, phrase degeneration, and roles/negation/quantities. Its examples distinguish actual content changes from boundary risks. For example, GLM's missing 都 is not silently called a proved logical reversal; retaining 17.3 and entity names is not treated as proof of latent semantics. No confirmed role swap or changed numeric value was seen in the reviewed primary role/quantity examples; this is not a semantic audit of all 300 outputs.

This package is a **READ_FULL structural pilot**, not a complete v1.2 D1 release. Exact raw text and geometry are preserved, but student tokenizer alignment, executable B+/B- event compilation, prediction-before-forcing loss consumption, a real student consumer, RETURN/Lookback/coupling/forgetting examples and continuous latent training remain unimplemented. Targets stay in supervision metadata; no teacher latent or summary is inserted into student observations. `input_complete` on an MDN excerpt is not true document EOF. No output may be forced as an early READ_STREAM action.

All input and result records have `training_eligible=false`. Old v0/v0.2 releases, splits and pending human-review status remain intact. This pilot compares proposed lexical and phrase candidates; it does not change the locked deterministic word-boundary baseline. A production upper-level teacher should take an already stabilized lower-level node set when that policy has been selected, as required by v1.2 §10.5.

Word-node counts include literal whitespace and punctuation children. A two-child phrase containing one lexical word plus a space is not evidence of semantic compression. The recorded node ratio is only a property of this explicit serialization, not a bitrate or a compression-quality result.

The `0`/`1` scale projection refers to the pilot's word/phrase candidate levels, not finalized student model scales. No student tokenizer has been selected or aligned by this package. Supplementary inspection of the first eight expansion outputs (one per template) also finds hard-valid but all-singleton phrases and budget-driven cuts, so even Qwen3.8's relative primary-sample advantage is not a robust-quality certificate.

## Running

From the repository root, use the existing `.venv-word-boundary` Python environment (3.12.14, jieba 0.42.1):

```powershell
python -m training.generation_v1_2.local_pilot_2026_11_04.download --only all
python -m training.generation_v1_2.local_pilot_2026_11_04.prepare
python -m unittest training.generation_v1_2.local_pilot_2026_11_04.test_validate training.generation_v1_2.local_pilot_2026_11_04.test_model_evidence -v
python -m training.generation_v1_2.local_pilot_2026_11_04.run_all
python -m training.generation_v1_2.local_pilot_2026_11_04.audit
```

The local native backend uses the existing trusted Microsoft C++ runtime directory only in its child-process PATH; no global driver or environment modification is made. The desktop's restricted process environment cannot access the GPU reliably, so native inference is run with host access. Completed document records are skipped on rerun. Changes to the frozen generation protocol require a new experiment directory. Re-running `prepare` refuses differing existing frozen inputs.

`hard-check-summary.json` contains recomputed cohort metrics. `audit.json` checks complete receipts, fixed requests and stopped sessions. `manifest.json` hashes all tracked experiment artifacts except itself, including code, raw outputs, review and this report; `.gitattributes` disables newline normalization for this directory. See `DATA-NOTICE.md` for source/annotation attribution and licenses.

`model_evidence` fetches only small official metadata/configs and reads local GGUF headers/tensor directories; it does not load tensor values or restart inference. Existing raw evidence is reused, with derived MTP scope counts recomputed. Eight focused geometry/visibility/parameter-scope tests pass; exact output is preserved in `test-report.json`.

## Results

The first 28-case cohort is complete. Qwen3.6 passes hard checks on 13/28 first attempts and 13/28 after the allowed retry (15 retries). Qwen3.8 improves from 15/28 to 20/28 (13 retries). GLM improves from 3/28 to 4/28 (25 retries). These are format/geometry/raw-preservation outcomes, **not semantic accuracy**. Among the four independent MDN cases, Qwen3.8 hard-passes three; the other two hard-pass none.

For those 28 inputs, client annotation time including retries is 122.91s for Qwen3.6, 586.97s for Qwen3.8 and 144.67s for GLM, excluding model loading. Recorded output tokens per annotation wall second are 26.43, 5.67 and 27.25 respectively; responses have different lengths, and errors are included rather than hidden. No output hits the 2048-token cap and no reasoning text is returned in this cohort. GLM's local speed advantage over dense Qwen3.8 does not establish more **quality-approved** examples per GPU-hour: hard survival and qualitative failures remain separate, and MI300 is untested.

The 12-case qualitative inspection per model is complete, covering 36 primary outputs plus supplementary inspection of the other final pilot hard failures. Under this frozen interface, **Qwen3.8-27B is the most useful next baseline**: it gives several defensible local groups and the highest raw-faithful survival. Qwen3.6 is often coarse or collapses multiple clauses into one phrase. GLM often proposes natural phrases quickly, but systematically deletes spaces/punctuation; it also drops 都 in one contrast fixture and splits a protected signed number. The observed difference therefore cannot be reduced to harmless formatting, and current pass counts do not rank the models' intrinsic linguistic capability.

The 72-template expansion is complete under the same settings. Qwen3.6 hard-passes **42/72 first/final**, Qwen3.8 **28/72 first → 42/72 final**, and GLM **0/72 first/final**. Thus the two Qwens tie on final hard survival in the template cohort; Qwen3.8 requires 44 retries there versus Qwen3.6's 30. Its relative advantage must not be overstated as a universal win. The supplementary first-eight-per-model review also finds singleton degeneration, budget cuts and, in GLM expansion:005, the actual rewrite 不是说 → 说不是.

Across each model's 100 inputs, first/final hard checks are **55→55** for Qwen3.6, **43→62** for Qwen3.8 and **3→4** for GLM. There are **499 preserved attempts** (145/157/197), no transport errors, no output-cap truncations and no returned reasoning. Total annotation wall time including retries but excluding loading is **343.02s / 2069.48s / 415.31s**. The 100-record aggregate mixes diagnostics and related templates and is not an independent natural-language accuracy estimate. The original 28 and 72 cohorts remain separately reported in `hard-check-summary.json`.

All 300 model/document records are audited against fixed inputs, prompt/schema/sampling settings, raw-response revalidation, asset/config hashes, GGUF tensor-dimension counts and stopped server sessions. Eight focused tests pass. The primary qualitative sample is 36 outputs; the extra first-template sample is 24, and supplementary pilot failure notes are explicitly outside the primary denominator. No human gold is accepted.

None is production-qualified by this pilot. A practical next revision should give the teacher the stabilized lower-level node IDs and request only ordered grouping/boundaries, letting the compiler retain raw bytes, whitespace and punctuation. This is consistent with v1.2 §10.5 and may reduce copy errors; it is **a hypothesis, not a tested rescue of GLM**. Freeze that new interface and use new natural hold-outs before MI300 generation. It must still resolve lexical policy, tokenizer alignment, event legality and student-consumer checks.
