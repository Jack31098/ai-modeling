## 暂定建议及推演

首个可复现基线采用 **Qwen3.6-35B-A3B，GGUF Q8_0，llama.cpp 的 llama-server，Windows Vulkan 后端**。

理由是本轮的事实、数值和事件真值可由程序产生，teacher 主要负责自然语言表达与候选监督；先保留较高权重精度，同时给批量生成与缓存留余量。较小激活规模预计有利于吞吐，但这只是硬件与结构推导，尚无本机性能证据。Q8 是保守起点，也不保证比 Q6 更划算；只有在保真率不下降时，才因实测收益调整量化。

保持同一 GGUF、提示集、上下文、输出预算和并发配置，再对比 Vulkan 与 gfx1151 HIP/ROCm。最终由稳定性、有效样本吞吐和内存峰值决定后端，不预设其中一个必然更快。先使用近期兼容构建验证，再固定实际通过验收的 build/commit；不把持续追随 latest 当作复现方案。

Qwen3.5-122B-A10B Q4_K_M 作为后续质量对照候选。只有在同一测试集上提高事实保真、复杂指令或监督候选质量，且总生产成本可接受时，再提升其角色。参数更多不证明它在本任务上优于 Qwen3.6-35B-A3B。首轮不同时常驻两个模型；122B Q5 的内存余量尤其需要实测。

Qwen3.6-27B dense 是另一质量对照候选，不作为首个吞吐基线。[官方模型卡](https://huggingface.co/Qwen/Qwen3.6-27B)中的通用基准不直接回答本项目的数据保真问题；其与 35B MoE 的实际性能取舍仍需在本机和本任务上比较。

LM Studio 可用于人工检查提示与输出；批量生产优先直接调用 llama-server，以固定启动参数、模板、采样、版本和日志。vLLM/SGLang 留给后续部署平台与批处理需求变化时评估，不为当前选型先迁移系统。

## 数据生产边界与最小例子

候选流程：程序生成内容记录与可检查状态 → Qwen 从同一记录独立生成不同表述 → 程序执行结构、语义和时序校验 → 按内容组划分并写出数据。

例如记录规定“甲持有 ID 3719，乙持有 ID 6824”，生成器可以改变叙述顺序，但不得交换持有人。仅检查输出包含两个 ID 不足以验收；最初采用可核验的受限表达或显式实体绑定，复杂自然语言还需独立抽查。JSON Schema 只约束形状，不能证明语义正确。

输入输出分别保存 Observation Tape 与 Supervision Tape；event id、available_at、provenance 和 causal/hindsight 类型由协议控制。程序生成可执行事件的参考轨迹，teacher 可提供表达和弱监督候选，不能任由 teacher 捏造已发生的运行事件或未来收益数值。

同前缀、多未来分支用于检查：相同可见前缀的因果动作标签不能因本次真实未来而互相矛盾；未来依赖价值进入 hindsight 通道。所有派生表述与未来分支按同一内容组隔离划分。

“真正缺失”须在可检查的模拟状态中先严格定义，验证所有合法 scope、F 历史与可重算规则都不能提供答案。模拟器的 NOT_FOUND 只构成该环境的真值，不能声称已经证明真实学生 latent 中没有信息。接入学生后需要重放/运行协议及行为检查；不能仅按对话间隔自动标成遗忘。

## 验收、失败条件与下一步

初始配置建议：纯文本，不加载视觉 projector；每请求约 16K 上下文作为短任务起点；先并发 1 再试 2/4；表述生成默认关闭 thinking，复杂候选监督可单独测试开启。上下文与并发是待验配置，不是完整推理基准配置。以启动日志核验实际每 slot 容量，不能混淆总 context 分配与每请求上限。

先用约 100–200 个可检查内容记录建立小样本验收集，覆盖角色绑定、数值、否定、条件/时序、输入与输出 lookback、late promotion、真正缺失补问。计量：语义校验通过率、监督泄漏、重试/截断率、总耗时、有效样本/小时、prefill/decode 吞吐和内存峰值。通过样本/小时包含过滤、重试与校验成本，不能只报告裸 token/s。

若 35B 输出语法合格但频繁交换角色、遗漏否定或产生不可验证标注，当前模型/提示/任务拆分不足；应定位失败再对比 27B、122B 或收紧生成范围。若高并发降低有效吞吐、后端回退 CPU、出现 OOM 或长时间不稳定，降低并发/上下文并重新计量，不把容量可装入当作可生产。

下一步核验实际系统、GPU 可见内存和驱动，搭建一套 llama-server 与可复现客户端；随后确定最小内容与事件 schema，做小样本端到端生成、校验与后端对照。上述部署和推理实验尚未完成。
