# RX 7900 XTX 上的 Cola2 BF16 实测

日期为 2026-11-16（America/Los_Angeles）。对象为 ByteDance-Seed 的 Cola2 base checkpoint。实验从 `c15a4a697dcba5bb46035987faa8c01145aaa980` 建立独立验证分支，沿用官方短提示 `Question: What is the capital of France? Answer:`，batch 为 1，`max_new_tokens=32`，设备 RNG seed 为 `42`。运行采用官方模型类、本地离线权重与 PyTorch MATH SDPA。目标是在这台独显机器上验证加载、短生成、参数设备和显存占用。[固定模型](https://huggingface.co/ByteDance-Seed/Cola2/tree/db876b905cf719b60da33c12a75021ac111f7a67) · [固定官方源码](https://github.com/ByteDance-Seed/Cola2/tree/085817168c9d6a718812fbc0075b968fc4cd5f9f)

## 设备与加载路径

Windows 设备记录和 WSL HIP 均识别为 AMD Radeon RX 7900 XTX `gfx1100`。Windows 驱动为 `32.0.31041.5005`，WSL 为 Ubuntu 22.04.5，ROCm 包为 `10.1.0-3`。Windows 设备记录为 25,753,026,560 bytes，WSL HIP 可见容量为 25,725,255,680 bytes，AMD SMI 显示 24,533 MB。分别保留各接口的原始口径。[设备与环境](../experiments/cola2/results/rx7900xtx-wsl-2026-11-16-environment.json) · [AMD SMI 静态字段](../experiments/cola2/results/rx7900xtx-wsl-2026-11-16-amd-smi-static.json)

WSL 没有既有 PyTorch 或本模型权重。独立 Python 3.10.12 环境安装 AMD 的 PyTorch `2.14.0+rocm10.1.0`、Transformers `4.57.6`、safetensors `0.8.0` 和 accelerate `1.15.0`。D 盘检查约有 207 GiB 可用，固定权重源包含 8 个 FP32 文件，共 35,072,206,700 bytes。权重和依赖分别放在 D 盘资产目录与 D 盘 WSL 虚拟磁盘内。[安装来源](https://rocm.docs.amd.com/projects/ai-ecosystem/en/latest/frameworks/pytorch/install.html?rocm-ver=10.1.0) · [实际环境锁](../experiments/cola2/results/rx7900xtx-wsl-2026-11-16-pip-freeze.txt)

考虑到 WSL 约有 15.6 GiB 主存，选择 `device_map={"vae": "cuda:0", "dit": "cuda:0"}`。按固定版本 Transformers 的加载实现，CPU 侧逐张量读取和转型，转换后的权重进入同一块 GPU。这避免在 CPU 先构造完整 BF16 模型，也避免在显卡上暂存最大的 FP32 张量。小型 BF16 matmul 与因果注意力得到预期值，95,686 参数的随机 Cola2 生成了 3 个 token。另存随机 FP32 模型为 4 个小分片，通过相同加载映射恢复为全 GPU BF16，核对了参数、缓冲及加载键。[小模型预检](../experiments/cola2/results/rx7900xtx-wsl-2026-11-16-tiny.json) · [预检遥测](../experiments/cola2/results/rx7900xtx-wsl-2026-11-16-tiny-vram.json) · [小分片加载日志](../experiments/cola2/results/rx7900xtx-wsl-2026-11-16-tiny-load.log) · [Transformers 加载路径](https://github.com/huggingface/transformers/blob/v4.57.6/src/transformers/modeling_utils.py#L627-L721)

首次虚拟环境引导由于跨 shell 路径解析问题，在原项目根目录生成了几个临时 venv 项。确认其创建时间和内容后，移入 D 盘忽略的实验资产目录留存。原项目的 Git 状态恢复到开始时，已有两个 B 模块文件仍在原位置。首次取得源码时，获取回执把已解析的 D 盘路径当作 C 盘工作树子目录，取相对路径失败。验证分支修正回执路径后，重跑核对已取得的源码并写出回执。

## 正式运行结果

2026-11-16 16:06–16:08（太平洋时间）的正式运行通过。八个 FP32 分片均按官方 SHA-256 核验，实测回执与固定资产锁逐个一致。检查点索引覆盖 1,137 个张量，加载无缺失、多余或尺寸不符的键。全部 8,768,019,912 个参数均为 BF16，位于同一 `cuda:0` 的 RX 7900 XTX，另有一个 FP32 持久缓冲也位于 GPU。VAE 和 DiT 的设备映射均为 `cuda:0`，CPU 参与读取、转换和调度，推理采用全 GPU 驻留，无 CPU 或磁盘 offload。[权重回执](../experiments/cola2/results/rx7900xtx-wsl-2026-11-16-download-verification.json) · [源码回执](../experiments/cola2/results/rx7900xtx-wsl-2026-11-16-source-receipt.json)

固定输入含 11 个 token，模型输出 32 个新 token，内部经历 3 轮生成和 24 次去噪。加载及准备输入用时 **114.55 秒**，GPU 同步计时的生成用时 **16.00 秒**。以下为实际续写，保留原始空格、重复和截断。开头正确回答了 Paris，后续出现重复、错误人名和未完成短语。本次只测一条短提示。

```text
 Paris. Question: Who is the the president of France? Answer: Nicolas Harko Question: Who is France's most minister? Answer: Nicolas Hark
```

- PyTorch 加载阶段峰值 allocated **16.332 GiB**（17,536,385,024 bytes），reserved **16.338 GiB**（17,542,676,480 bytes）。
- PyTorch 生成阶段峰值 allocated **16.446 GiB**（17,658,732,032 bytes），reserved **16.471 GiB**（17,685,282,816 bytes）。
- AMD SMI 基线为 **2,295 MB**，设备占用采样峰值为 **17,347 MB**，发生在生成阶段。加载阶段采样峰值为 **17,339 MB**。481 条周期样本加两条端点样本均成功，单位为 AMD SMI 原始报告的 `MB`。采样覆盖全设备，瞬时峰值未测。PyTorch 与设备遥测口径分开报告。

运行器保留了 token IDs、配置、阶段时长、分配器读数和全部设备遥测记录。启动日志含 Transformers 的 tokenizer 正则、`torch_dtype` 弃用和 GenerationMixin 提示。沿用固定模型的 tokenizer 配置，此次提示词 ID 与既有实验记录核对一致。分支上的控制台日志替换了本机用户目录前缀，原始控制台日志留在 D 盘实验资产目录。[完整运行 JSON](../experiments/cola2/results/rx7900xtx-wsl-2026-11-16-full.json) · [控制台日志](../experiments/cola2/results/rx7900xtx-wsl-2026-11-16-full.log)

## 复跑命令

以下在 `Ubuntu-22.04` 中运行，工作目录为检出验证分支的工作树。此工作树的 `models/cola2` 映射到 D 盘的 `D:\Projects\ai-modeling\models\cola2-7900xtx`。已有校验回执和环境时设置 `venv`，再运行最后两条命令。每次使用新的 `run-id`，工具会拒绝覆盖旧 JSON。

```bash
python3 -m experiments.cola2.acquire source
python3 -m experiments.cola2.acquire model --workers 4

python3 -m venv --without-pip "$HOME/.venvs/cola2-7900xtx"
curl --fail --location https://bootstrap.pypa.io/pip/pip.pyz -o "$HOME/.venvs/cola2-7900xtx/pip.pyz"
venv="$HOME/.venvs/cola2-7900xtx"
"$venv/bin/python" "$venv/pip.pyz" install --no-cache-dir --index-url https://stable.repo.amd.com/rocm/whl-next/ 'torch[device-gfx1100]==2.14.0+rocm10.1.0'
"$venv/bin/python" "$venv/pip.pyz" install --no-cache-dir --index-url https://pypi.org/simple transformers==4.57.6 safetensors==0.8.0 accelerate==1.15.0 psutil==7.2.2

"$venv/bin/python" -u -m experiments.cola2.run --device cuda --dtype bfloat16 --tiny --seed 42 --sample-device-vram --run-id rx7900xtx-tiny-replay-01
HF_ENABLE_PARALLEL_LOADING=false "$venv/bin/python" -u -m experiments.cola2.run --device cuda --dtype bfloat16 --direct-device-load --generation-only --seed 42 --max-new-tokens 32 --sample-device-vram --run-id rx7900xtx-full-replay-01
```

显存遥测在导入 PyTorch 前同步取一条设备基线，再以约 0.25 秒为目标间隔调用 `amd-smi metric --mem-usage --json`。设备读数包含桌面及其他 GPU 客户端，且瞬时尖峰可能处于两次采样之间。PyTorch allocated 与 reserved 来自进程内分配器，在生成前重置峰值，保留单独的加载与生成阶段读数。[AMD SMI CLI](https://rocm.docs.amd.com/projects/amdsmi/en/latest/how-to/amdsmi-cli-tool.html)
