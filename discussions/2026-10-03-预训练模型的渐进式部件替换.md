# 预训练模型的渐进式部件替换（2026-10-03）

## 用户修正与目标

用户明确：增量式不要求逐层往上加，也不要求从一个一层语言模型开始。可以从已有语言能力的预训练模型出发，逐步替换部件，并要求撤掉旧部件后，新部件仍能让系统工作。上一轮把可训练的一层小模型当成通用语言能力的起点，误解了方法要求；该路线已撤下。用户要求本轮基于问题本身推演，不继续用论文清单代替方案。

当前对象是一类标准 causal decoder Transformer，具有逐层 KV cache。以下讨论是候选替换实验，未指定实际模型、未运行代码或训练，不声称其他混合架构具有完全相同的接口。

目标继续包括：已知输入可整体理解、减少输入阶段无必要的输出计算；生成时复用已完成的中高层计算、减少底层重做；逐步获得更粗粒度及可展开的层级。每一次结构变化都应从可用模型出发，并在旧路径真正停用后验收。

## 第一性约束：替换的是有状态的计算

把当前模型某段计算记作 F：它读取已有状态与当前信息，交付当前出口表示，并改变后续会使用的状态。候选 G 必须接管后续能观察到的接口。

因此替换接口要求可能包括 hidden state、各层 KV、位置、路由或累积状态；只拟合当前输出向量不充分。应追踪后续调用到底读取什么，以此决定需要交付哪些量。接口要求之外、没有消费者的中间计算可以直接省去，不必要求新部件重建全部教师内部过程。

在普通带 KV 的 decoder 中，已知 prompt 的最末层历史位置的最终输出不被后续 token 读取；该层未来 attention 需要的是由该层输入形成的 K/V。若实现仅需最后位置的 logits，相关历史 query/FFN 计算可按依赖关系审查是否可省。这个判断限定于上述计算图，具体运行库是否已经优化需检查；不能把本来就不需要的计算算成学习出新语义结构。

## 候选首个替换：生成阶段底层的一小段计算

### 为什么先从生成路径找接口

模型在选择 x_t 前，已经对 x_<t 完成了深层计算；前一步的中间/高层状态 s_(t-1) 已存在。实际选出 x_t 后，普通路径再从 embedding 出发处理这个 token。

待验证假设：s_(t-1) 中有一部分信息，足以帮助便宜的新部件直接构造当前 token 在某个浅层切口的状态。它不保证高层一定保留了需要的信息；可比较几个已存在的中间/高层读出，而不先指定最后一层最合适。

这种输入在逐 token 生成时自然可用。如果用同一路径读 prompt，则需要先得到前一个位置的深层输出，会引入串行依赖。因此它首先适用于生成，不应当作输入预填充路径的直接替代。

### 一个具体的最小切口

先选择预训练模型最底部一个 block 中昂贵的 attention 聚合与 FFN 计算，保留整台模型作为起点。教师在同一真实前缀上给出这个 block 的出口 h_1,t。新增一个较便宜的 G：

G(s_(t-1), embedding(x_t), position/state) → estimated h_1,t。

原来的后续层照常消费 estimated h_1,t，继续生成下一 token。G 接收的 x_t 是实际已选出的 token；s_(t-1) 只来自过去，不可偷偷读取当前 token 尚未执行的深层结果。

这一切口有一个便于验收的性质：第一层 K/V 由该层输入，即 token embedding 经相应归一化/投影/位置处理得到。它们可以继续按原公式生成并存入缓存，不必执行被替换的 attention 聚合与 FFN。这样旧部件的昂贵生成计算可以关闭，同时给下一次完整读入保留所需的第一层历史缓存。

这个候选替换的是上述计算部分，并非声称第一层所有算子或权重都被删除。G、保留的 KV 投影、额外状态的成本都要计入。若以后扩大到多层，深层 KV 依赖中间状态，接口要求随之扩大，不能沿用“一层的缓存容易维护”作为多层证明。

## 如何让旧部件退出

1. 固定现有模型作教师，收集普通文本及模型实际生成轨迹中的合法输入和切口出口。先训练 G 接近出口，必要时对不同中间层来源做小范围比较。
2. 把 G 真正接入原模型，用后续 token 的交叉熵和教师输出分布差异校正。原模型其余部分可以先冻结；冻结参数不等于后续层无需前向或反向计算，训练成本仍要计入。
3. 让新路径连续运行多步，逐渐覆盖长生成与读写切换。G 要适应自己引起的后续状态分布，不能只在教师状态输入上拟合单步。
4. 验收时完全关闭所选旧计算。检查生成、长程一致性、精确细节和下一轮输入，并测全部成本。教师只作为离线对照，不能在部署中暗中纠错。

状态向量误差可用于启动，但最终判断是旧计算停用后，后续任务是否正常。保留旧部件随时救场可用于开发，却不能作为“新部件已接管”的证据。

用户所说的“逐步”在这里可以是扩大替换范围、改变某个模块的状态表达、压缩一部分历史访问、或合并重复计算；没有必须按深度从下往上的顺序。

## 已知输入路径的另一种接口

输入已知时，未来生成通常通过各层 KV 读取历史，而不重新执行所有历史位置。这给另一个候选接口要求：从已有的较低/中间层表示，直接构造一小组较高层的历史 KV，替代这些历史位置上为了构造 KV 所需的后续完整计算。

首步可保持 KV 形状与消费者不变，由原模型提供 KV 及后续预测监督。继续处理 prompt 最后位置或另行满足首 token 所需出口；不能只交付缓存却遗漏首个生成分布。若拟合失败，说明所选输入/替代器容量/切口不合适；不意味着可以任意冻结中间接口。

这个方案也尚未验证，当前不与输出候选一起大规模改造。它说明原来的两种目标可以从同一预训练模型的不同可观察接口逐步切入，而无需先训练一套新的 E/C/D。

## 怎样接近更粗粒度与输出树

第一次替换可以保持一进一出的细粒度接口，先确认知识与行为能迁移。之后再试把一段包含多个细计算的局部计算图交给一个新部件：用一个持续的粗状态及较便宜的子计算，交付原来多个步骤所需的输出与结束状态。

若新部件真实接管多个子步骤，它就构成一个可继续替换/组合的父节点。这个父节点的边界取决于在哪些内容和状态下能维持后续行为，不能由“每 N 个 token”或节点数量直接宣布语义抽象。

生成方向尤其要保证：粗状态只从已知历史产生；子 token 按正确条件分布产生；展开结束后交付后续核心需要的状态。若只给出一段文本，却让原模型把整段重新计算才能续接，则所谓省计算可能只是推迟了旧计算。

这里提出的是让局部替换可以逐步扩大为层级的接口要求，尚未给出已经有效的自动树发现算法。是否能用同一粗状态可靠驱动多个子步骤，需要在一次替换成功后单独验证。当前不规定最终树深、分支数或 E/C/D 职责。

## 反例与失败判断

- G 的输入遗漏必要信息：两个前缀在所选 s 与当前 token 上近似相同，教师却需要不同的出口/后续行为。此时需要补充可访问状态、换切口或保留该计算，不能只增加蒸馏轮数。
- 单步拟合很好，自由生成后误差累积：说明训练状态分布或新状态动力学没有接管。
- 输出正常但下一轮输入失败：缓存接口要求不完整，或旧计算只是被推迟到了模式切换。
- 新部件必须调用原部件才能判断是否可信：尚未实现独立替代；该调用成本需要计入。
- G 接近被替代部分的成本，或省 FLOPs 却没有端到端收益：没有获得当前设置下的实用节约。
- 多步替换只在固定模板上成立：可以作为局部能力保留，不足以宣称一般语义层级。

## 暂定判断与下一步

增量路线的起点应是已有能力的预训练模型。一个候选首步是在生成模式下，利用已有中高层状态和实际 token，替代底层一个明确计算部分，并保留完整状态接口。其吸引力是有教师、可关闭旧路径、可连续运行验证；能力和成本收益尚待实验。

本轮没有决定最终架构或声称完整路径已可行。下一步需要选定真实模型后，画出一个切口的全部消费者，测所需出口能否由当前可用信息以更低成本构造。该结果决定扩大、改换还是放弃这个局部替换。
