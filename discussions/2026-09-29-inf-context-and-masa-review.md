## 对象、目标与评价尺度

- 前一文档主要解决：有限 HBM 下保存、压缩和调用长历史；核心对象是缓存、语义载荷与检索索引。
- MASA 主要解决：用不可变的内容流与可变的思想流分工，让内部状态参与记忆修订和推理；核心对象是双流之间的信息与训练信号。
- 这次的关键可观察量：思想状态对答案的独立因果贡献、纠错的局部性及依赖一致性、未知未来任务的泛化、总计算与内存成本。触发 F1、attention KL 和压缩率是辅助指标。
- 以下“文档提出”是来源事实；“缺口”“建议”是基于其明确方程与流程的分析。未把文档愿景或论文宣传性解释作为已证事实。

## 1. high_level_design.md 的价值与问题

### 值得保留的设计

文档已有主机内存分层、模型内部的归档/检索触发、Q-Former 压缩、soft-prompt 回注、可学习 Trimmer 和图式组织。它明显超出了普通“摘要 + 向量数据库”。

其中最有价值的两项分离：

1. **检索键 H 与语义载荷 D 分离**：适合匹配的向量和适合供模型使用的内容不一定相同，双塔索引建立在压缩载荷之上，使两者可独立评价。
2. **活动 KV 裁剪与归档内容分离**：先保存 pre-trim 快照再裁剪，避免用裁剪后的残余数据生成永久记忆。

同主题/实体但版本或细节不同的困难负例、随机标识与局部定义，也比仅凭主题相似性判断召回更有诊断价值。Explanation 与 reconstruction 的组合是合理训练建议，但其效果仍需实测。

### 问题 A：RoPE 重定位不等于上下文重算

标准 RoPE 的缓存键可写成 `k_i = R(p_i) W_k h_i`。反旋再旋转到新位置得到 `R(p'_i) W_k h_i`，其中 h_i 仍然由原上下文产生。拼接改变前缀、可见 token 或块间交互时，新运行需要的 h'_i 不保证等于 h_i；V 同样依赖旧上下文。

因此要区分：在同一执行历史里恢复原缓存页，和把旧块作为新前缀拼成另一段上下文。前者可以是缓存恢复；后者一般需要近似容忍、局部重算或专门训练的独立记忆接口。文档的 re-phasing 不能单独保证“无缝拼接”。[CacheBlend](https://arxiv.org/abs/2405.16444) 正是针对非前缀 KV 复用的上下文依赖，通过部分重算进行补偿。

### 问题 B：FP8 KV 不能作为逐字引用的无损存档

量化本身有损，KV 也不是保证可逆的原始 token 编码。即使保留未量化 KV，也不能直接把生成式还原称为逐字准确。

建议以原文/token IDs 和来源元数据作为精确证据，KV 作为有模型版本与上下文适用条件的加速副本。对于仅要求生成质量相近的路径，量化 KV 仍可能有工程价值。

### 问题 C：重构损失不保证信息完整

文档把 reconstruction 描述为确保 D 信息完整，这个结论过强。低平均 CE 可与少量关键标识丢失同时发生；teacher forcing 下解码器还可能依赖已给出的前缀和语言先验。

应分别评估原文重构、随机细节保留、未知查询及反事实替换。不能仅凭 4096→32 的 token 数比值断言信息论上不可能：高维 latent 的比特容量可能相当大；真正未证实的是可靠编码、可读出性和泛化。

**暂定定位**：这是值得复用的语义记忆与分层存储基础设施。其 research claim 应具体落在压缩、读写对齐或成本上；单纯扩大可保存上下文的长度不足以承载当前 vision。

## 2. MASA 的实质推进

MASA 已经明确提出：

- Content 作为不可变的发言/证据流，DSL 作为可变工作记忆；共享底座但通过 LoRA 区分功能。
- 学习何时 pause-and-reflect；区分 NEW、RECALL、UPDATE、CONFLICT。
- 内容位置和思想位置分别计数，跨流尝试去除显式距离偏置。
- Stage A 文字 DSL，Stage B latent 与可变记忆，Stage C 组合 codebook。
- Oracle 先标注内容，再调整因果位置，并设计了数据试点与困难事件采样。

这已是主动内部记忆的架构假设。尤其“历史记录保持不变，当前理解允许修订”很适合处理纠错与证据保留。上一轮建议中把文本 scaffold、latent 化、记忆操作作为新起点，未充分考虑用户已设计到这个阶段。

然而文档中的“外部检索或普通上下文无法提供这些能力”没有得到证明。可变状态的潜在优势应落在效率、可训练性、可靠修订或泛化上，不应先宣称表达能力严格优于所有文本系统。

## 3. MASA 最关键的机制缺口

### 3.1 思想流回到内容流的通道主要被定义为 mask

按 §4.1 和 §5.4–5.5，明确的信息路径是：`DSL → MPN → 选择原文范围 → content attention mask → 继续回答`。Content 的方程只显式读取 content K/V；没有明确规定 content 如何直接读取 DSL 的语义载荷或新推导出的结果。

由此得到的条件性推论：若内容状态和后续 mask 相同，修改 DSL 中的结论不会直接改变下一个 content 输出分布。这不否认 DSL 可以通过选择证据改善推理，但它限制了对“独立 latent 工作空间”的验证：状态中算出的新结果不能仅靠重新指向输入，就自动成为回答可读取的结果。

**建议**：保留 MPN 作为寻址/计算策略，另定义思想状态的直接读出通道，例如 memory cross-attention、latent prefix 或带门控的残差接口。先固定取证范围，验证思想状态本身是否有效，再测稀疏选择的收益。

这项建议用于补全 MASA 既有双流目标所需的信息通路。

### 3.2 Stage B 的 attention 蒸馏目标不足以证明 latent 推理

文档在冻结底座和 LoRA_DSL 后，用可训练 Query Embeddings、MPN 和 attention KL 进行 latent 过渡。但注意力矩阵相同不保证载荷、输出或新任务表现相同：`A V` 同时依赖 A 与 V。

训练需要区分：学到了“看哪里”的短查询，还是存下了当前事实、关系、规则及推理中间结果。attention KL 可以作辅助，未来任务的答案/行动损失应成为主要约束。

Query Tokens 的实现还需澄清：共享可训练查询作为种子，经当前上下文计算出 `z_t = F_phi(C_<=t, M_(t-1), Q)` 是可行路线；如果每个训练样本的 activation 直接对应一个独立学得向量，则未定义未见事件如何生成状态。文档文字在这两种解释之间不够明确。

冻结底座仍允许损失通过它反传到记忆模块；不必因此从头训练整个模型。是否冻结 DSL adapter 和读出接口，应由 latent 过渡后的适配效果决定。

补充数学问题：如果 `A_pred` 是归一化非负 attention 概率，逐行 L1 恒为 1，文档的 `L1_sparsity` 不会产生预期稀疏梯度。稀疏约束应作用于门控/选择数量或实际资源成本，具体还需定义。

### 3.3 可变 DSL KV 的更新与依赖失效尚未定义

已经生成的后继 DSL 状态可能吸收旧节点内容。删除或覆盖旧节点，不会自动清除这些后继状态中的旧结论。Ring buffer 描述了存储布局，没有解决语义依赖。

例如预算由 2000 改为 3500，系统还应处理“某方案超预算”的旧结论；若同金额属于两个不同项目，还要避免改错对象。

建议维护稳定节点身份、版本、来源及必要依赖。模型可以通过语义匹配选择目标，由 runtime 执行稳定地址更新，不必生成字符串 ID。读出时过滤过期版本，并采用重算、刷新或训练过的更新规则处理派生状态。

§7.1 自动把节点绑定到最近一段 content，只解决创建位置；RECALL/UPDATE/CONFLICT 还需要表达它们引用的多个旧来源和被修订节点。

### 3.4 Oracle 的位置合法性未覆盖选择策略的因果性

两次标注流程确实能减少“总结提早引用未来事实”。但“现在已知道某事实”和“现在知道未来会问这个事实”不同。

最小反例：两条训练样本有完全相同的前缀，其中同时出现事实 A 和 B；后半段分别只问 A 或只问 B。全知 Oracle 可能在同一前缀下分别选择保存 A 或 B，即使所有 summary 内容都已出现。部署策略此时无法预知分支。

因此 hindsight 标签可用于发现候选记忆与训练价值估计，却不能直接作为部署策略能完美模仿的时机/重要性真值。建议用相同前缀的不同未来分支评价记忆，以 prefix-only 审查验证可见信息，并把最终任务表现作为判据。Pass 3 不应仅核实措辞是否可能由前缀产生。

### 3.5 NoPE、触发器及组合编码需保留为实验假设

- **NoPE**：去掉直接 RoPE 距离项不等于纯语义或已完成对齐；hidden states 仍可能带有上下文位置信息。时间、先后、版本等语义不能随坐标偏置一起丢掉。文档已经提到存 raw keys 或独立投影，应明确选择实现；仅对一个 query 做统一逆旋一般不能抵消所有不同位置的 key。
- **触发器**：能在完整上下文回答冲突问题，不证明稀疏上下文下某一个 h_L 必然包含冲突信号。MLP 是合理原型，但“信息必然存在”不是证明。漏掉唯一关键修订可能不可恢复；误触发也可能写入错误状态，不能一概归为轻微成本。
- **Stage C**：聚类不证明组合语义。`[FOOD]+[RISK]+[USER_ATTR]` 尚未表达具体食物、论元角色、否定及时间。需要测试角色交换、否定、未见组合和多步组合；codebook 可作为可选研究分支，不宜作为 Stage B 必然成功后的结论。

## 4. 与已核查工作的关系

截至本次可核查资料，“主动触发 + latent 记忆”已存在直接相关工作，上一轮主要列文本记忆作为起点确实不充分。

[MemGen](https://arxiv.org/html/2509.24704v2) 采用 trigger 与 weaver，在固定 reasoner 上按需生成并注入 latent memory；因此它是比普通 RAG 更接近 MASA 的比较对象。不过其 §4.3 把经历学习放进 weaver 参数，也可接外部检索，并不等于 MASA 所设想的部署期固定参数、持久可寻址和可修订节点图。

[MEMORYLLM](https://arxiv.org/abs/2402.04624) 研究 latent memory pool 的自更新，也应列为相关基线。相关论文支持部分组件可以训练，不能据此认定 MASA 的完整机制已被证实、完全重复或已失去价值。

**暂定研究定位**：从同预算的 latent 记忆与内部触发方案继续，重点研究持续可变状态的局部修订、来源/依赖一致性，以及同一组证据条件下状态本身对后续推理的帮助。

## 5. 修订后的下一步

建议以 MASA 为起点，保留 high_level_design 中 D/H 分工、归档与活动内存分离等基础设施。近期不重建通用文本记忆系统；如需文本版本，将其作为现有设计的 scaffold、诊断工具或对照组。

1. **补全双流接口**：明确思想状态读写、内容流直接读取思想状态、MPN 寻址、证据与版本分别如何传递。写出可执行的数据流与损失，而不是扩大功能列表。
2. **做最小 latent 闭环**：少量动态状态槽位，固定触发与固定证据范围；用未来任务结果训练写入/读出，验证冻结底座下是否有收益。早期不强求稀疏、跨层 goto 或 codebook。
3. **加入修订与多步递归**：先确保状态能改变输出，再测试局部更新及派生结论刷新。若 latent 化尚难，可短暂保留文本槽位辅助定位，避免把文本→latent 与只追加→可修改同时变化后无法归因。
4. **加入学到的触发和层次调度**：当状态确实有用后，再优化何时算、查哪里及保留多少；用延迟、内存和任务回报评估，触发 F1 作为辅助。

三个优先实验：

- **直接读出实验**：固定提供给解码器的原文与选择 mask，比较正确思想状态、打乱状态、替换关键结论和禁用读出。若模型对状态内容始终不敏感，尚未建立预期的工作记忆通道；若错误状态也不影响答案且原文可直接解题，要结合必须利用已形成结果的任务排除旁路。
- **修订一致性实验**：相近实体的两份预算或两套规则，一处纠正，只改变相关事实及其派生计划，保留无关结论和原始历史；同时比较文本/latent 和只追加/可修改两个独立维度。
- **同前缀多未来实验**：同一经历后提出不同、未事先透露的任务，观察记忆能否支持它们，避免事后挑选记忆产生虚高成绩。

**停止或转向条件**：如果所有收益都来自更好的取证，主张应收窄为内生检索/路由；如果直接 latent 读出在匹配预算后有收益，才扩大可变状态推理。如果显式状态更可靠，保留显式部分；如果层次或 codebook 无额外收益，不把它们设为完成 vision 的必经步骤。
