# v1.2 样本生成模型与 MI300 生产方案

日期：2026-11-04，America/Los_Angeles。用户明确暂不推进 H-Net fused 内核，开始 v1.2 实现，先准备样本；
随后纠正硬件定位：**Ryzen AI Max+395／128GB 只是测试机，正式生成将租用 MI300**。
MI300 的型号、卡数、供应商及预算未确定。本轮仅选型和保存官方小型元数据，没有租机、下载新权重或运行生成基准。
工作从 `250cbb1` 的干净目录开始，分支 `codex/v1.2-sample-generation`。

## 对象与 v1.2 要求

选择的是外部样本生成／结构标注 teacher，不是学生 F 的预训练底座。最新口径仍为先训 B，F／最终展开器从头训练，
0.8B 是目标规模。沿用 v1.2 §10，首要交付 D1：原文＋参考树／森林＋尺度投影＋可执行事件＋监督权限。
生成原文、标注结构、提供协议示范不必由同一个模型负责；无需把所有自然语料都改成 LLM 合成文本。

现有固定词边界管线只是第 0 步参考件，不冒充完整 D1。首层已有确定规则时，LLM 优先在已形成的叶单元上提候选上层结构。
不把教师摘要或 hidden 当作学生 latent 真值；READ_STREAM 必须再经前缀一致性／因果审核，事件合法性尽量由程序编译检查。
程序校验跨度、覆盖、无环、顺序和预算，含义保真由独立检查与人工抽查补足；多个 LLM 同意不等于金标。

## 官方版本核查：事实

查阅[Qwen3.8-27B](https://huggingface.co/Qwen/Qwen3.8-27B)、
[Flash-Next](https://huggingface.co/Qwen/Qwen3.8-Flash-Next)、
[2.4T-A95B](https://huggingface.co/Qwen/Qwen3.8-2.4T-A95B)及官方 HF API：

- **Qwen3.8-27B**：27B dense 语言模型，发布包包含视觉组件；BF16 与官方 FP8 分别发布。模型卡为 Apache-2.0。
- **Qwen3.8-Flash-Next**：125B 主干、6B 激活，另有51B n-gram embedding与4B MTP；不能把125B当作整个发布包的权重总量。
  官方卡另用 Qwen Community License 1.0，不能沿用27B的Apache许可假设。存在商业用途附加条款，本轮不对未来商业部署作权利结论。
- **Qwen3.8-Max／开放权重名2.4T-A95B**：2.4T总量、95B激活；也有FP8发布，许可与27B不同。
  不建议作为首个低成本批量生成基线。
- 官方 Qwen HF API 本次返回上述三个能力档各自的常规／FP8仓库，共6个。
  这不是全部API产品目录；Omni／语音等独立产品不纳入本次纯文本 D1 选型。

[GLM-4.7-Flash](https://huggingface.co/zai-org/GLM-4.7-Flash)为30B-A3B MoE；
[GLM-5.3-Flash](https://huggingface.co/zai-org/GLM-5.3-Flash)为320B总量、18B激活，默认reasoning_effort=max。
不能把“GLM”当成一种规模或用Flash后缀判断速度。两者官方卡均标MIT。

[候选元数据](../training/generation_v1_2/teacher-candidates-2026-11-04.json)固定8个仓库的revision、精度分组与观察日期，
状态均为未下载／未benchmark。按官方safetensors参数数×dtype字节数估算：27B BF16约55.56GB、FP8约30.86GB；
Flash-Next FP8约185.49GB；GLM-4.7-Flash BF16约62.44GB；GLM-5.3-Flash约328.25GB。
这些是已索引张量的存储估计，包含发布的组件；**不是运行HBM占用**，不包含未计入的量化元数据、缓存、workspace、通信及allocator余量。
[MI300X官方规格](https://www.amd.com/en/products/accelerators/instinct/mi300/mi300x.html)为192GB HBM3；
Flash-Next FP8在单卡上余量较小，是否能装下和并发容量仍须实测，不保证单卡高吞吐。

## 暂定建议与推演，不是实测结论

按**先用1张MI300X建立基线**的规划假设：首选 **Qwen3.8-27B BF16** 跑通 D1 质量基线，
同卡／同精度用 **GLM-4.7-Flash BF16** 作速度与质量对照。选择27B基线的理由是给缓存和批量留余量、
控制变量及许可较简单；不是已经证明它的树标注优于GLM。再以27B官方FP8测试量化的合格率／吞吐变化。

如果采用2卡预算，将 **Qwen3.8-Flash-Next-FP8** 和 **GLM-5.3-Flash** 纳入更大teacher对照；
先验证各自架构、量化与ROCm内核支持，模型卡写支持框架不等于相应MI300部署已通过。
两卡运行大模型还应与两份小模型单卡副本比较，不能忽略卡数和通信成本。
2.4T-Max不作首发全量生成器，可在确有质量缺口时另行评估，不据此授权租用更多卡。

GLM-4.7-Flash激活规模较小，推测有低单token算量优势；但高批量dense计算效率、MoE路由、prefill／decode比、
思考token、输出长度与过滤重试都会改变排名。GLM-5.3-Flash则不能仅靠“Flash”假定更快。
本轮没有同平台同工作负载数据，不写任一型号确定的tokens/s或胜出结论。

云端框架先以 **Linux＋vLLM ROCm** 为候选基线，SGLang按具体模型配方对照；
[vLLM官方安装说明](https://docs.vllm.ai/en/latest/getting_started/installation/gpu/)列出MI300/gfx942。
正式镜像、ROCm／框架commit、精度和启动参数必须在实际云卡验收后锁定，不把本机Windows H-Net环境当作云生成栈验收。

## 最小对照与失败条件

先准备约100–200条固定内容与标注任务，覆盖中英文、角色／否定／数量／单位、条件时序、混合文字与歧义，
并让所有候选处理同一组原文、固定尺度预算和输出schema。简单表述生成先试不思考，复杂结构标注单列受控思考预算；
不把不同模型默认最长推理的总耗时混为同等任务。原文及派生族先分组，独立人工审核集不能回流训练／调参。

统计几何合法率、因果违规、独立语义抽检、截断／重试、输入字符覆盖和最终 **合格样本／卡时**，
同时报告卡数、上下文、并发与包括reasoning在内的输出预算。不同tokenizer的裸token/s不足以决定生产方案。
若快模型的角色／否定错误增加、树不合法或需要大量重试，就不能仅凭decode速度判定更划算。

下一步先在测试机固定任务书、schema、校验器与小样例；确认云卡配置后做短对照，再决定量产teacher。
