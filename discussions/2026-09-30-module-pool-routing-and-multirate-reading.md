# 模块池、序列路由与多粒度输入处理（2026-09-30）

## 用户提出的问题

用户提出一条新的推演：MASA 借用已有 LLM，而更自由的动态 recurrent vision 可能需要从头预训练；生成训练似乎要求逐 token 处理，但理解希望“一目十行”。进一步把固定 Transformer 层视为可调用专家，构建模块池，由记住历史选择的路由器决定调用顺序，并随课程加入新专家。

本记录整理该设想、修正前提，并对照原始研究。未运行模型实验；候选接口和课程均是待验证建议，未确认实现计划。

## 定义、尺度与目标

- **模块/专家**：用户设想中是单个 Transformer block，即 attention、FFN 及相关残差和归一化组成的变换。名称不意味着它已有独立可解释的专业能力，也不同于常见的仅 FFN 专家。
- **参数身份**：模块编号表示使用哪组权重。
- **执行步**：一次状态更新；同一模块可以在不同执行步被调用，参数身份不再等于固定深度位置。
- **输入位置与粒度**：更新对象可以是 token、片段或工作状态。此轴与使用哪个模块分别定义。
- **一目十行**：包含需要分别检验的两层含义：高层可以针对聚合状态低频更新；已经读到的一段输入可以参与整体解释，不把早期位置表示永远限制于当时的前缀。用户随后明确强调了第二层的信息可见性，不能以硬件并行性替代讨论。两者均不保证语义上无损。
- **目标/可观察量**：生成与理解质量、每位置及每粒度的模块调用数、质量随额外计算的变化、新专家利用与旧能力保持，以及端到端延迟、训练开销、KV 和活动内存。

## 需要修正的三个前提

### 已有预训练 LLM 不能直接任意重排，但仍可能提供初始化

“完整 vision 不受普通冻结底座直接支持”不推出“预训练参数没有价值、只能从零开始”。需区分：冻结底座加接口、从已有权重初始化并继续训练、从随机权重预训练。

[Mixture-of-Modules（MoM，EMNLP 2024）](https://aclanthology.org/2024.emnlp-main.1164/)采用已有 Transformer 模块初始化，再联合训练模块与路由器。这是与当前设想十分接近的反例。它不证明任意大模型都能廉价转化。

[Relaxed Recursive Transformers（ICLR 2025）](https://arxiv.org/abs/2410.20672)研究把预训练模型改造成共享层的循环结构，并通过继续训练及按深度的低秩适配恢复性能。此证据针对受限循环，不能外推为任意专家路径已可用。

### 计算并行与因果信息可见性必须区分

输入 prompt 已知时，标准 dense decoder-only 可对所有位置并行执行某一层，然后进入下一层；训练时 teacher forcing 也不要求逐 token 串行前向。新 token 的常规自回归采样才存在逐步依赖。参见实际部署团队关于 [prefill/decode 的说明](https://huggingface.co/blog/tngtech/llm-performance-prefill-decode-concurrent-requests)。

因此用户的三层四 token 例子有 12 个 token×block 处理位置，但不能据此说一定有 12 次串行 block 调用或等量延迟；attention 还包含跨位置运算，计数不是精确 FLOPs。标准 prefill 更接近 F1(X_1:4) → F2(H_1:4) → F3(H_1:4)。流式输入可逐 token 到达，但这是输入到达方式的约束。

用户随后纠正：所说的语义串行是 causal mask 的前缀信息约束。此前用 prefill 并行性回应，没有对准其关注点。硬件并行事实仅用于限定调用次数和延迟的计量，不能用来否定语义方向性。

标准因果模型的每一层位置表示 h_i 只能依赖 x_1:i；后文不能回流到早期位置表示。位置 n 可综合全部 x_1:n，因此该约束不意味着模型完全不能理解整段，也不是 RNN 那种必须经过所有相邻位置的串行状态链。参见 [Transformer 原论文 §3.1、§3.2.3](https://arxiv.org/html/1706.03762v7)。

最小例子：后文可消除前面 bank 的歧义，但原 bank 位置在标准因果前向中的表示不会因此改写；后续位置可以形成消歧后的解释。若目标是让原有多个状态相互校正，则需要改变可见范围或另设可修订工作状态。单纯跳层、换专家及保持相同 mask 的反复计算，都不移除这个约束。

因此除算子、粒度、扩容外，还必须明确第四个维度：**信息可见性与状态修订**。已知输入可以在预测回答前双向交互；不能把这种含后文信息的状态用于预测同一输入中的较早 token，否则泄漏目标。可考虑区分输入理解与输出生成的 mask/状态，但这是待验证设计，不要求两者一定使用不同权重。

用户希望高层少执行的动机也仍成立：并行处理不会自动省掉每个位置的高层工作。应同时观察信息依赖、状态更新和实际资源成本。H-Net 的因果分段支持高层低频更新，不能作为解除前缀可见性限制的证据。

### 说话能力不是粗粒度编码的已知逻辑前置条件

可以联合训练编码器和自回归解码器，通过输出损失学习输入表示；也可以保留细粒度输出预测，同时使内部高层在少数边界更新。能从每个位置预测后续内容，不要求每个内部模块都在每个位置执行。

[H-Net（2025）](https://arxiv.org/abs/2507.07955)学习动态分段与层级压缩，并保留因果自回归语言建模。它支持“粗粒度内部处理与生成训练可以共存”，不证明压缩已经具备人类略读能力，也不涉及任意模块池。

“先训练稳定生成，再放开粗粒度处理”仍然可以是一种课程偏好，需要与联合训练比较。仅训练 encoder 且没有生成接口/目标，确实不能自动得到生成能力；但不能据此认定必须事先训练好 decoder。

## 与设想接近的研究

### 最直接：Mixture-of-Modules

[论文 §3、§4 与附录](https://aclanthology.org/2024.emnlp-main.1164.pdf)定义 attention 模块池、FFN 模块池及 SKIP；两个 GRU 路由器根据当前表示和路由隐藏状态逐步选择模块。它拆分 attention/FFN，粒度比用户提出的整个 block 更细。

作者报告随机初始化联合训练容易出现模块同质化，因此从 Transformer 初始化模块，再训练模块和路由器；实验采用 GPT-2 规模，并把路由限制在若干模块分组中。固定最大组装步数与有限分组应明确区别于无限制全局执行图。此处的模块分组也不是把输入 token 聚合成片段。

这个先例直接支持两项判断：序列路由器是可研究的设计；预训练模型可能正好提供模块分化的启动条件。它没有证明课程中不断扩容的整个 block 池、跨粒度读写和自主学习的联合 vision。

### 动态计算次数：Mixture-of-Recursions

[MoR（2025）](https://arxiv.org/abs/2507.10524)共享一组层，并为 token 分配不同递归深度；还处理递归相关的 KV 缓存策略。它接近“不同输入获得不同计算量”，主要控制重复深度，并不等于在任意专家之间自由选择顺序。

### 不同粒度的更新频率：H-Net

H-Net 对应“一目十行”的粒度侧：在保持细粒度输入/输出的同时，让内部主网络处理压缩序列。它说明生成目标、因果约束与高层较低更新频率可以共同设计。

### 随分布变化增加容量：Lifelong-MoE

[Lifelong Language Pretraining with Distribution-Specialized Experts（ICML 2023）](https://proceedings.mlr.press/v202/chen23aq.html)通过增加专家、保留旧专家及正则化来继续预训练。它支持专家扩容这一组成部分，仍主要处于固定层级中的 MoE；没有证明新专家可在任意深度与旧专家自由组合。

这些工作分别覆盖模块组合、循环深度、输入粒度和参数扩容。当前不能把它们的结果相加，宣称完整系统已被验证。

## 对用户调用序列的进一步形式化

用户例子：普通路径每个位置调用 1→2→3；新路径为 1,2,1,2,3,1,1,2,3，其中模块 1 调用四次、模块 2 三次、模块 3 两次。

它表达了计算频率差异，但还没有说明：每次操作更新哪个位置/片段/持久状态，模块 3 收到的是最新 token 还是多个位置的聚合，以及何时消费新输入、何时输出。

因此一个执行事件至少应标出“模块身份、读写对象、可见输入边界”。同一模块可以重复作用于同一状态；不同位置也可以各自选择路径；把多个位置汇总到一个高层对象则还需要聚合与后续访问接口。

只开放专家 ID 选择，不能自动实现输入片段合并或高层状态更新。反过来，多粒度更新也可以使用固定算子顺序。建议先把模块组合与粒度调度分开验证。

## 候选路由器与扩容接口（推测）

一个候选形式：路由状态 r_(k+1) = G(r_k, summary(S_k), embedding(a_(k-1)), budget_k)，再对候选专家 j 使用共享评分函数 score_j = f(r_(k+1), key_j)。S 是当前可见工作状态；动作执行后更新 S。

- 决策必须能够依赖当前计算结果，仅记住专家 ID 序列容易学成与输入无关的固定程序。
- 序列记忆可帮助部分可观察的路由器，但不是必要定理：如果当前工作状态已充分包含决策信息，前馈路由也可能有效。应做有/无历史状态的消融。
- 此处递归主要沿计算步展开；若另设一个跨所有文本位置的串行控制器，会额外牺牲 prefill 并行性，需单独论证。
- 对候选集合逐项评分便于增加专家条目，但不赋予路由器理解新专家能力。固定分类头也可扩展输出行，两种接口都需训练与校准。
- 新专家初始较弱，可能永远不被选择；新评分也可能抢走旧专家流量。可研究克隆与受控分化、有限探索、旧任务回放/蒸馏和逐步扩大可选动作，但不存在即插即用的保证。
- 新课程可以先检验既有专家能否解决，再决定是否新增容量。“每个课程一定新增专家”是设计选择，不是已证明的最优策略。

## 训练和执行中尚未解决的问题

1. **因果性**：预测 x_(t+1) 的表示、分段边界和路由决策均不能使用 x_(t+1:)。已知 prompt 可被整体编码后预测回答；这与用其未来内容帮助预测 prompt 自身 token 是不同训练目标。
2. **attention/KV 语义**：专家 attention 要访问哪些对象，前面未执行同一专家的位置是否有可读 KV，同一专家重复调用时读取哪一版状态，均须定义。权重共享不自动意味着不同执行步 KV 可共享。
3. **模块组合分布**：模块在原路径有效，不保证重排后有效；课程需训练新路径上的输入分布。专家同质化或集中使用少数专家均可能发生，均匀负载本身也不等于良好分工。
4. **计算预算**：无预算约束可能总选择最长路径；过早强罚成本可能导致早停塌缩。必须比较质量与实际成本，而非仅比较参数量或调用个数。
5. **硬件并行性**：少量不规则调用、调度和 KV 管理可能抵消 FLOPs 收益。上界调用次数和可批处理路径是候选工程约束，不代表理论上必须固定深度。

## 暂定研究顺序与可证伪条件

候选顺序：从可训练的常规小模型/已有权重开始，保留已知有效的路径；局部开放少量块的跳过和重复；比较静态、仅当前状态路由、带历史状态路由；在这之后分别研究更粗粒度更新与新增专家，再检验两者结合。

- 若自由路径不优于资源匹配的固定或受限路径，暂不扩大路由自由度。
- 若历史状态不改善质量/成本或稳定性，则无需坚持路由器一定为序列模型。
- 若扩容收益仅来自更多参数/训练量，与普通扩宽相同，则尚未证明可组合扩容的价值。
- 若高层执行更少但精确引用、否定词、长距离约束等任务退化，则需要保留细节访问能力，不能把压缩率直接当成理解效率。
- 成功指标不仅是语言 loss 降低，还包括生成质量不明显受损、计算分配随内容变化、以及新专家加入后旧任务能力保持。

## 本轮结论与后续

用户的模块池视角有明确先例，并为动态 recurrent 提供了比“任意层 goto”更具体的对象；最直接的 MoM 还给出预训练模块与序列路由的启动方法。这修正了“已有 LLM 大概率帮不上忙”作为默认前提的判断。

真正需要同时但分别研究的是：选择什么算子、在哪个粒度更新、如何增加新的算子，以及已知后文是否可以参与修订早期状态。保持生成监督并不要求所有算子逐 token 执行；但同一输入内的逐位置 next-token 监督与双向编码不能无条件共用状态。“先会说话再会略读”仍应记录为候选课程，而不是逻辑必然。

下一步最有价值的是对照 MoM 与 H-Net 明确最小状态和读写接口，判断当前优先验证模块组合还是高层低频更新；原版 MASA 保持不变。尚无实验支持完整联合架构的优势。
