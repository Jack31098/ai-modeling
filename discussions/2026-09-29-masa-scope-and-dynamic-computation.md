# MASA 的设计边界与动态递归目标（2026-09-29）

## 问题与来源

用户指出：已 fork 的 MASA 与近期分享对话存在明显差距。二者都希望训练模型主动操作 context，但动态 recurrence、skip layer、中间层进入/退出等能力已经超出 MASA 的原始执行设计。因此需要判断 MASA 能否独立成立、是否存在上限，以及是否适合作为更大目标的架构基础。

来源：[MASA 原版设计](../masa.md)、[近期分享对话](../share-world-labs-transcript.md)第 31、35 个消息、[MASA 技术评估](2026-09-29-inf-context-and-masa-review.md)、[fork 记录](2026-09-29-masa-fork.md)。本记录是架构分析和候选方向，未运行实验；提议的新目标尚未被用户确认为完整实现计划。

## 对象、定义与可观察量

- **对象**：固定部署参数下，模型如何组织内部记忆、迭代状态并调度计算。训练时允许适配参数；部署参数固定与训练时冻结底座是两个约束。
- **时间尺度**：输入到来、内部思考迭代、公开输出、长期记忆更新分别计数，不假定一步思考必须对应一个新增 token。
- **MASA 的独立目标**：在共享语言模型底座上建立内容/思想双流，学习触发反思、关联历史、修订记忆并改变后续信息访问。
- **近期目标的扩展**：让模型还可选择执行哪些计算块、重复多少次、何时停止，以及如何在不同粒度状态间转移。
- **可观察量**：相同任务与资源预算下的质量、实际块调用轨迹、每块参与状态数量、迭代次数、活动内存、延迟，以及长期状态一致性。编码器、控制器、跨尺度转换和解码器成本都计入。

## 暂定判断

MASA 可以形成独立而有意义的研究目标，但当前文档仍有读出与修订语义等未闭合接口。即使这些问题全部补齐，现有路线也不完整覆盖近期的动态计算目标。

其明确边界在于可选择的操作：MASA 主要开放了模型调用之间的调度与记忆访问；对单次模型调用内部的层执行路径，仍沿用普通 Transformer。增加训练数据不能直接产生 runtime 没有提供的中间层回路或跳层操作。

不能据此断言 MASA 具有已经证明的通用智能或任务准确率上限。完整模型反复运行、配合外部状态，也可能完成同样任务。这里讨论的是可直接表达的计算调度方式、归纳偏置，以及有限资源下的效率潜力。

## 1. MASA 已有什么动态性

按 §5，MASA 已有可学习的反思触发、Content/DSL 切换、持续生成到 DSL_END 的可变长度过程。Stage B 还提出 PUSH/POP/UPDATE。因此把它说成完全没有递归或动态控制是不准确的。

但这类动态性主要发生在完整前向调用之间。按当前定义，生成一个文字或 latent DSL token 仍通过既有底座的层序列；切换 LoRA 改变变换参数，没有为模型提供“只重复中间计算块”这样的运行操作。

MASA 已解耦思想 token 与公开输出 token。近期 vision 还要求进一步解耦：内部迭代次数与新增思想 token 数量、状态粒度与物理网络层、输入读取进度与高层计算次数。

## 2. 记忆组织与计算调度是可交叉的两条轴

可写记忆可以配固定深度计算；动态深度模型也可以不具备长期可写记忆。二者都有效，并不证明联合系统一定更好。

在记忆图中，节点可能表示事件或命题，边表示来源、时间或依赖。在计算图中，节点表示某次算子执行，边表示状态传递。整理记忆图可能改变计算需要访问哪些对象，但不会自动为执行图添加新的回路。

稀疏 attention 选择某层可访问的历史，通常仍保留该层及后续层的前向计算。跳层则要求部分状态不执行某些 attention/MLP；重复计算块又要求状态重新进入可迭代的变换。这些是不同机制，需分别定义。

相关原始研究支持这种区分：[Universal Transformers](https://arxiv.org/abs/1807.03819) 重复应用共享变换并引入按位置停止；[Huginn](https://arxiv.org/abs/2502.05171) 在语言模型内部迭代 recurrent block；[Mixture-of-Depths](https://arxiv.org/abs/2404.02258) 学习选择各层参与 attention/MLP 的 token。这些组件结果不证明完整多层可变记忆系统的效果。

## 3. 原路线为何不会自然长成新目标

### A→B→C 主要改变表示介质

从文字 DSL 到连续 latent，再到离散组合 codebook，主要回答状态如何编码。即便 Stage C 成功，也可能仍然是每个内部 code 都完整通过底座。表示被压缩，不意味着网络内部执行路径可变。

### 调度器的观察位置限制可节省的工作

MASA 的 Activation Head 读取最终层 h_L 来决定是否反思。这能决定接下来是否再做额外计算，却不能省掉当前 token 为得到 h_L 已执行的高层计算。

若要在中间位置决定停止或跳过后续块，就需要在决策点已有的中间状态上作选择；不能依赖尚未付出成本计算出的最终表示。

### 冻结原底座与既有蒸馏目标限制适配方式

LoRA 可以帮助适配新读写接口，但在固定执行器中，LoRA 本身不增加跳层或循环指令。新路径还需要训练反复进入同一块、跨表示空间转换及停止后的读出。

以完整底座 attention 为主要模仿对象，适合训练访问策略；它不足以教授 teacher 未展示的计算调度。应以任务结果和真实资源成本评价新执行过程，teacher 的答案、轨迹或表征可作为辅助，不要求逐层注意力一致。

## 4. 最小例子与边界

设底座有 32 层，完成输入编码后还需要五轮关系更新。现有 MASA 可以生成更多 DSL 状态并反复调用底座；文档没有定义把一个固定容量工作状态留在内部，只重复某个共享的 8 层计算块五次、最后再读出结果的执行方式。

这个例子只说明两种架构允许的计算路径不同，不证明 8 层块能获得相同能力或五轮一定够用。必须训练并比较其计算质量与全部开销。

另一个例子是流式输入：每个小片段先更新局部状态，只有形成某个事件或需要更复杂判断时才启动高层计算。仅在完整 h_L 产生之后选择是否归档，无法实现对当前片段高层计算的提前节省。

边界：动态跳层可以节省不必要计算，但不直接增加推理步数；递归可以增加计算，但不自动形成层级记忆。更自由的路由可能造成状态失配、路由开销、批处理效率下降和训练困难。

## 5. 若采用更大目标，需要重新定义哪些部分

候选的总体目标是：**在任务质量与资源约束下，学习维护、访问和更新内部状态，并决定对哪些状态执行何种计算、重复多少次以及何时输出。**

需要先明确四个接口：

1. **工作状态**：有哪些可独立更新的状态对象，哪些是证据、推理草稿或持久记忆；不同粒度状态之间怎样转换。物理层深度与语义抽象程度不预先画等号。
2. **计算操作**：哪些块可重用、哪些路径可跳过、哪里允许进入或退出，以及读写状态的作用范围。不同块的输入输出空间必须兼容或有适配器；任意层间 goto 不能仅靠同维度张量成立。
3. **控制策略**：根据当前可见状态选择读取证据、更新工作状态、执行某块、继续迭代、改变粒度或停止输出。初期可以限制为少量合法路径。
4. **训练目标**：任务质量、未来任务适应、状态一致性和实际计算/内存预算。区分减少步数与降低总成本；跟踪早停错误和困难样本表现。

MASA 的内容/思想分工、来源关系、部分记忆操作和数据构建经验可在其中复用。其完整前向、DSL 序列及 A→B→C 顺序应作为可替换的实现选择，不宜充当最终系统必须遵守的边界。

在这个候选框架中，MASA 可以对应一种受限配置：执行器总是调用完整底座，状态主要是 DSL 节点，策略主要决定何时调用与访问哪些历史。这是建模关系的建议，不是对两套系统数学等价的证明。

## 6. 如何继续而不偏离目标

此前建议优先修补 MASA 的直接读出与修订一致性，解决的是局部闭环。用户这次提出的是更高一层的目标选择；因此应先明确最终是否研究可变内部计算，再决定哪些 MASA 修补值得投入。

若选择动态递归作为核心，一个更贴近目标的最小原型是：输入编码一次，维护固定容量 latent 工作状态，反复调用共享计算块，通过读出接口产生回答。先使用固定迭代次数，然后学习停止；之后再加入第二种状态粒度或第二个计算块，检验选择性执行和跨尺度访问。

这条顺序直接测试“同一状态反复计算”是否有用，同时把记忆组织作为可结合的能力。无需先完成全部 MASA 的 codebook、稀疏检索与复杂触发器，再等待动态递归出现。

关键对照与失败条件：

- 对比匹配资源的完整底座循环与共享内部块循环；只减少参数量、latent 数或名义 FLOPs 不足以证明收益。
- 在相同状态容量下增加迭代，检验质量是否改善；反复错误或退化会削弱该更新算子的价值。
- 检查执行轨迹，确认路由真正改变了计算，而不仅改变了 attention 可见范围。
- 若更自由的路由无净收益，保留受限回路；若可写记忆对目标任务没有额外收益，也允许把动态计算与长期记忆分别研究。
